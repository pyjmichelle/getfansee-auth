## 1. 品牌 — Noir Cabaret 色彩系统

### 双层逻辑（先判断再选色）

```
这是主操作按钮 / CTA / 选中态？
  → 酒红 (--wine) #8B313A

这是认证身份 / 等级 / 已付费状态 / 付费档位高亮？
  → 香槟金 (--premium) #C9A876

都不是？
  → 中性色（surface / border / text ramp）
```

**金色出现频率 < 2%。** 普通界面看不到金色——金色只在「已经花过钱或值得花钱」的身份场景出现。

## 2. 字体规范

### 字体选择

| 角色     | 字体           | CSS 变量       | 用途                                      |
| -------- | -------------- | -------------- | ----------------------------------------- |
| 正文     | Hanken Grotesk | `--font-sans`  | 全站默认：UI、按钮、标签、正文            |
| 展示标题 | Fraunces       | `--font-serif` | **仅限**页面级 `h1`、品牌时刻、营销大标题 |
| 等宽     | system mono    | `--font-mono`  | 代码、金额数字（tabular-nums）            |

**Fraunces 使用约束：** 仅页面大标题（如登录页品牌语、creator/[id] 姓名）；Studio 仪表盘、表单、导航、admin 全部用 Hanken Grotesk，不出现衬线字体。

### 字号 Scale（1.2 模比，基准 16px）— utility class 强制

| 级别    | Utility class   | Mobile | Desktop (lg+) | 字重 | 行高 | 用途                 |
| ------- | --------------- | ------ | ------------- | ---- | ---- | -------------------- |
| Display | `.text-display` | 32px   | 48px          | 600  | 1.1  | Fraunces，页面大标题 |
| H1      | `.text-h1`      | 24px   | 32px          | 700  | 1.2  | 页面标题             |
| H2      | `.text-h2`      | 20px   | 26px          | 600  | 1.2  | 区块标题             |
| H3      | `.text-h3`      | 16px   | 20px          | 600  | 1.3  | 组件标题             |
| H4      | `.text-h4`      | 14px   | 16px          | 600  | 1.3  | 小节标题             |
| Body-LG | `.text-body-lg` | 16px   | 18px          | 400  | 1.6  | 正文长文             |
| Body    | `.text-body`    | 15px   | 16px          | 400  | 1.5  | 普通正文             |
| Small   | `.text-small`   | 13px   | 14px          | 400  | 1.4  | 次级说明             |
| Tiny    | `.text-tiny`    | 11px   | 12px          | 500  | 1.3  | 标签、时间戳         |

**根字号：16px**（原 13px 是全站显小显挤的元凶，本版本恢复）

**强制规则（v5 新增）**：内容排版**必须**使用上表 utility class（已在 `globals.css` §7 实现，自带 MB→PC 响应式双档）。页面代码禁止用 `text-sm` / `text-lg` / `text-[15px]` 等手写字号承载内容层级——那正是"设计稿字号不复现"的根因。Tailwind 原生字号类仅允许出现在与内容层级无关的微组件内部（如 Badge、按钮 label 由组件统一控制）。

金额数字使用 `font-variant-numeric: tabular-nums` 确保等宽对齐。

## 3. 间距与密度系统

### 8pt 网格

所有间距必须是 8 的倍数（4px 作为最小单位允许）：

| Token        | px   | Tailwind 等价     |
| ------------ | ---- | ----------------- |
| `--space-1`  | 4px  | `p-1` / `gap-1`   |
| `--space-2`  | 8px  | `p-2` / `gap-2`   |
| `--space-3`  | 12px | `p-3` / `gap-3`   |
| `--space-4`  | 16px | `p-4` / `gap-4`   |
| `--space-6`  | 24px | `p-6` / `gap-6`   |
| `--space-8`  | 32px | `p-8` / `gap-8`   |
| `--space-12` | 48px | `p-12` / `gap-12` |
| `--space-16` | 64px | `p-16` / `gap-16` |

**禁止任意值：** 不允许 `p-[13px]`、`mt-[17px]` 等。

### 页面密度三档

| 档位       | 受众                                         | 区块间距 | 卡片 padding | 特点                             |
| ---------- | -------------------------------------------- | -------- | ------------ | -------------------------------- |
| **沉浸档** | Fan 消费面（home、creator/[id]、posts/[id]） | 32–48px  | 24px         | 影像优先、大留白、每屏一个主 CTA |
| **工作档** | Creator Studio                               | 24px     | 16–24px      | 中密度、列表紧凑、数据清晰       |
| **工具档** | Admin 后台                                   | 16px     | 12–16px      | 高密度、信息优先、无装饰色       |

### 容器宽度

| 场景            | max-width            | 说明                                                                                                                                                    |
| --------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Feed / 帖子详情 | `672px` (max-w-2xl)  | 内容居中，两侧空气感                                                                                                                                    |
| Creator Studio  | `1152px` (max-w-6xl) | 宽表单、图表、数据表格（2026-07 从 5xl 上调，与已上线的 7/9 个 Studio 页面实际宽度对齐，同时修掉 studio 首页「加载骨架 5xl → 真实内容 6xl」的到手跳变） |
| Admin           | `1152px` (max-w-6xl) | 数据表格（2026-07 从共享 layout 的 5xl 误差修正为 6xl）                                                                                                 |
| Legal / 文档    | `768px` (max-w-3xl)  | 舒适阅读宽度（2026-07 合并两套重复的 LegalPageShell，修正误用的 max-w-4xl）                                                                             |

**强制要求**：每个 `<PageShell>` 调用点必须显式传 `maxWidth` 或 `noPadding`——不允许依赖裸默认值 `4xl`（该值不对应任何真实场景，纯粹是历史遗留，2026-07 已核实零调用点依赖它）。

## 4. 组件规范

### 按钮（3 档尺寸 × 5 变体）

**尺寸：**

| 档位 | 高度 | 横向 padding | 字号 | 用途                       |
| ---- | ---- | ------------ | ---- | -------------------------- |
| `sm` | 32px | 12px         | 13px | 辅助操作、标签、紧凑区域   |
| `md` | 40px | 16px         | 14px | 默认按钮（卡片、表单）     |
| `lg` | 48px | 24px         | 15px | 主 CTA（移动端所有主操作） |

移动端主 CTA 一律 `lg`（满足 44px+ 触控要求）。图标按钮固定 `40×40`。

**变体：**

| 变体          | 外观                 | 场景                                          |
| ------------- | -------------------- | --------------------------------------------- |
| `default`     | 酒红填充 / 暖白字    | 全站主操作（Subscribe、Follow、Save、Submit） |
| `premium`     | 香槟金填充 / 深色字  | 仅付费身份场景（档位购买确认、VIP 升级）      |
| `secondary`   | raised 面 / 次级文字 | 次要操作                                      |
| `ghost`       | 透明 / 次级文字      | 取消、关闭、次级导航                          |
| `destructive` | 橙红微填充           | 删除、封禁等破坏性操作                        |

**废弃：** `rose`、`violet`、`gold`、`purple`、`gradient`、`*-gradient` 变体全部废弃，改用上述 5 个语义变体。

### 徽章（Badge）

| 变体          | 场景                                           |
| ------------- | ---------------------------------------------- |
| `default`     | 通用                                           |
| `premium`     | 认证（✓ Verified）、VIP、Top Supporter、已解锁 |
| `success`     | 已订阅、支付成功                               |
| `destructive` | 违规、封禁                                     |
| `secondary`   | 标签、分类                                     |
| `outline`     | 中性信息                                       |

### 卡片

- 圆角：统一 `14px`（`--radius-lg`）
- 内边距：沉浸档 `24px`，工作档 `16px`
- 边框：`1px solid var(--border-subtle)`，hover 升为 `--border-default`
- **禁止嵌套卡片**（卡片内不放卡片）
- 背景：`var(--bg-surface)`（不再使用 glassmorphism blur）

### 输入框

- 高度：`40px`（与 md 按钮对齐）
- 圆角：`10px`
- 背景：`var(--bg-surface)`
- 边框：`var(--border-default)`
- Focus：`var(--border-wine)` 边框 + `var(--wine)` ring

## 5. 六态规范

每一个可交互组件必须定义以下六种状态：

| 状态              | 样式规则                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------ |
| **default**       | 基础外观                                                                                   |
| **hover**         | 颜色/边框过渡 `150ms ease-out`；禁 scale 位移；卡片 = 边框升 `--border-strong` + bg 升一档 |
| **focus-visible** | `1.5px solid var(--wine)` outline + `2px` offset（键盘导航可见）                           |
| **active**        | 颜色加深（`--wine-active`）；`transform: scale(0.98)`；无弹跳                              |
| **disabled**      | `opacity: 0.4`；`cursor: not-allowed`；`pointer-events: none`                              |
| **loading**       | 按钮内 `Loader2` spinner 替换文字；宽度 `min-width` 锁定防跳动                             |

所有可点击元素：`cursor: pointer`；触控目标 `≥ 44px`。

## 6. 响应式断点

| 断点    | px   | 说明                         |
| ------- | ---- | ---------------------------- |
| Mobile  | 375  | **设计基准**（优先移动端）   |
| Tablet  | 768  | 中间过渡（md）               |
| Laptop  | 1024 | 底栏 → footer 切换节点（lg） |
| Desktop | 1280 | 最终适配（xl）               |

**导航切换规则（PageShell）：**

- `< lg (1024px)`：底部 5 栏 BottomNavigation + 顶部简化 NavHeader
- `≥ lg (1024px)`：SiteFooter + 完整 NavHeader（搜索内联）

**Admin 后台：**

- `< lg`：AdminSidebar 改抽屉（Drawer）式，汉堡菜单触发
- `≥ lg`：固定 `240px` 左侧 sidebar

每页开发完成后须在 375 + 1280 双视口截图验证。

## 7. 去 AI 布局守则（强制）

以下布局模式**禁止出现**，违反即重做：

1. **禁同构卡片网格**：`[图标 + 标题 + 两行描述] × N` 的等大卡片阵列。改为主次分明的列表或分层布局（主指标 1 行 + 次指标列表）。
2. **禁全居中堆叠 hero**：`[居中大标题 + 居中副标题 + 居中按钮]` 三连。改为左对齐或不对称构图。
3. **禁 eyebrow 脚手架**：全大写字距小标签（`AVAILABLE BALANCE`、`ABOUT`、`PROCESS`）和 `01 / 02 / 03` 序号节标题。
4. **内容优先**：Fan 消费面以创作者影像为最大视觉单元，UI chrome 退后。每屏只允许一个主 CTA。
5. **不对称呼吸**：区块间距用 `32/48px` 交替制造节奏，禁止全页等距「贴瓷砖」。

## 8. Emoji 与图标守则

### 禁止

- **禁止在 UI 中使用 emoji**（`⭐🏆👑🎉🚀🖼️🎥☕✦` 等全部禁止出现在 JSX 中）
- 禁止「✓ Subscribed」文本勾——改 `<Check>` Lucide 图标

### 允许

- **`unit_emoji`**：打赏单位（buy-me-a-coffee 模式），由创作者自定义，属于**数据字段**而非 UI 装饰，允许在打赏组件中渲染

### 图标体系

全站统一使用 **Lucide React**（项目已安装）。替换对照：

| Emoji  | Lucide 替换            |
| ------ | ---------------------- |
| ⭐     | `Star`                 |
| 🏆     | `Trophy`               |
| 👑     | `Crown`                |
| 🎉     | `PartyPopper` 或删除   |
| 🚀     | 删除文案中的装饰 emoji |
| 🖼️     | `Image`                |
| 🎥     | `Video`                |
| ✓ 文本 | `Check` 图标           |
| ✦ 装饰 | 删除                   |

## 9. 空状态文案表

每个列表页必须有专属空状态（一句有人情味的文案 + 单一引导 CTA）。

| 页面                              | 空状态文案               | CTA                            |
| --------------------------------- | ------------------------ | ------------------------------ |
| Home feed（已登录，未关注）       | 还没有关注的创作者       | 去发现 → /search               |
| Home feed（Following tab 无内容） | 还没有关注的人更新       | 去浏览新内容                   |
| Notifications（空）               | 目前没有新通知           | —                              |
| Subscriptions（空）               | 还没有活跃订阅           | 发现创作者 → /search           |
| Purchases（空）                   | 还没有购买记录           | 浏览内容 → /home               |
| Creator posts（空）               | 这位创作者还没有发布内容 | —                              |
| Studio post list（空）            | 还没有发布过内容         | 发布第一篇 → /creator/new-post |
| Studio subscribers（空）          | 还没有订阅者             | 分享你的主页                   |
| Studio analytics（空数据）        | 数据会在有互动后出现     | —                              |
| Search results（无结果）          | 没有找到相关创作者       | 清除筛选条件                   |

## 10. 动效规范

- **缓动函数**：统一 `cubic-bezier(0.16, 1, 0.3, 1)`（ease-out-quart）
- **时长**：交互过渡 150ms，展示动画 250ms，慢速揭示 400ms
- **禁止**：弹性/bounce（`cubic-bezier(0.34, 1.56, 0.64, 1)` 已废弃）、scale > 1.02 的 hover 效果
- **保留**：`like-pop` 动画（点赞按钮，属于时刻性 delight）
- **reduced-motion**：所有动画必须提供 `prefers-reduced-motion: reduce` 回退
