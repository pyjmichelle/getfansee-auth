# Page IA Review — 逐页信息架构走查

> 目的：不是检查"功能能不能用"（那是 feature-qa-walkthrough），而是评审**布局该不该这样设计**。
> 每页产出可执行的布局建议，具体到"把 X 移到右栏、tab 改分段控件、弹层改页面"级别。

## 走查矩阵（强制）

每个页面 = **2 视口 × N 角色**：

- 视口：MB 375×812（设计基准）+ PC 1280×900
- 角色：按页面适用性选 `游客 / fan / creator / admin`；共享页面必须双角色对比截图
- 截图命名：`<页面>-<角色>-<视口>.png`（如 `me-creator-mb.png`），存 `docs/reports/screenshots/<date>-ia-review/`

## 每页评审模板（固定格式）

```markdown
### <页面路由>（<角色> / <视口>）

**现状分区**

- PC：左栏 = ...；中栏 = ...；右栏 = ...（无右栏则写"未利用"）
- MB：纵向顺序 = 1. ... 2. ... 3. ...

**问题**（按下方检查表逐项）

- F-XXX (P0/P1/P2): ...

**建议**

- 具体布局改法，可画 ASCII 分区示意
```

## 检查表 1 — 分区职责（PC）

- [ ] 左/中/右三栏各自职责单一？（身份/导航 | 主内容 | 辅助/上下文）
- [ ] 宽屏利用率：1280px 下主内容是否孤岛居中、两侧大片空白无信息？
- [ ] 视线动线：F 型（信息页）或 Z 型（营销页）是否成立？主 CTA 在动线终点？
- [ ] 每屏**只有一个**主 CTA（wine 填充）；其余降级为 secondary/ghost
- [ ] 相关操作是否物理相邻（编辑资料靠近资料区，不藏在页尾）？

## 检查表 2 — 纵向节奏（MB）

- [ ] 首屏（812px 内）是否包含：身份确认 + 核心内容开头 + 主 CTA？
- [ ] 拇指区（屏幕下 1/3）：主操作是否可达？破坏性操作是否**远离**拇指区？
- [ ] 纵向顺序 = 用户任务优先级？（不是 PC 布局的机械线性化）
- [ ] 长列表是否有粘性入口（sticky CTA / 回顶）？
- [ ] 无横向滚动；触控目标 ≥ 44px

## 检查表 3 — Tab 取舍决策规则

用 tab 的条件（**全部满足**才用）：

1. 内容是**同一实体的平行视图**（如 Following/For You、登录/注册）
2. 切换不丢失用户输入/滚动位置成本
3. 2–4 个选项（>4 改下拉或独立页）

不该用 tab 的信号：

- 内容有先后依赖（改用步骤条/wizard）
- 只有一个 tab 有实质内容（删掉 tab，直接展示）
- tab 内容是不同任务（改独立页 + 导航入口）
- 筛选/时间范围切换（改分段控件 segmented control，视觉上与导航 tab 区分）

## 检查表 4 — 点击反馈与弹出选型

**点击反馈**（六态之外的选型问题）：

- [ ] 点击后 <100ms 内有视觉反馈（active 态/spinner），无"点了没反应"死区
- [ ] 导航类点击：目标页骨架 ≤ 1s（超过 = 性能问题，记入性能清单）
- [ ] 可点击区域 = 视觉边界（整卡可点 vs 只有按钮可点，必须一致）

**弹出选型规则**：

| 场景                           | MB                    | PC                   |
| ------------------------------ | --------------------- | -------------------- |
| 轻确认/单选（登出、删除确认）  | 底部 sheet            | 小 modal（≤400px）   |
| 中表单（打赏、充值、分享）     | 底部 sheet（可拖关）  | modal（≤560px）      |
| 重流程（KYC、发帖、多步表单）  | **独立页**，禁 modal  | 独立页或全屏 overlay |
| 即时反馈（复制成功、保存成功） | toast（≤3s 自动消失） | toast                |
| 上下文预览（图片放大）         | 全屏 lightbox         | lightbox             |

- [ ] 弹出层必须可用 Esc/回手势关闭；MB sheet 支持下拉关闭
- [ ] 弹出内再弹出（modal 套 modal）= 违规，改流程

## 检查表 5 — 双角色差异

- [ ] 同一页面对不同角色的 CTA 正确（creator 看自己主页 = 编辑，fan 看 = 订阅）
- [ ] 角色专属入口（Studio、升级 creator）插入后布局不失衡
- [ ] 角色不可用的功能：隐藏 vs 禁用 vs 引导升级，选型是否一致？
- [ ] 空状态按角色定制（creator 空 feed 引导发帖，fan 空 feed 引导发现）

## 流程

1. 读 `DESIGN.md`（token/密度/断点基准）+ 历史截图基线
2. 起生产构建服务器（`pnpm build && pnpm start`，避免 dev 编译假象）
3. 按角色登录（`test-fan@example.com` / `test-creator@example.com`），逐页按矩阵截图
4. 每页套用模板评审，问题 F-编号 + P0/P1/P2 分级
5. 汇总到 `docs/reports/` 报告；全局性发现（弹出选型、tab 规则）写回 DESIGN.md 建议节

## 分级标准

- **P0**：布局导致任务失败/严重误导（主 CTA 不可见、角色 CTA 错误、弹出不可关）
- **P1**：明显低效/不一致（分区职责混乱、tab 误用、拇指区不可达、反馈缺失）
- **P2**：打磨项（宽屏利用率、间距节奏、文案）
